# Desktop & Android apps

PixelDeck ships as three things built from **one** web bundle:

| Target | Shell | Typical download |
|---|---|---|
| Web | Vite SPA on GitHub Pages | — |
| Desktop (Windows / macOS / Linux) | [Tauri v2](https://tauri.app) | 1.8 MB `.deb` (measured); 3.7 MB stripped binary |
| Android | [Capacitor](https://capacitorjs.com) | ~4–6 MB APK |

For scale: an Electron build of the same bundle would be around 120 MB.

There is no second codebase. `dist/` is the app; the shells only host a webview.

---

## Why these two shells

**Tauri, not Electron.** Tauri uses the webview the OS already has (WebView2 on
Windows, WKWebView on macOS, WebKitGTK on Linux) instead of bundling a whole
Chromium. That is the difference between a ~5 MB installer and a ~120 MB one.
PixelDeck is local-first: projects and assets live in localStorage/IndexedDB.
Exports use the native Save dialog and the filesystem plugin on desktop. The
main window receives only `dialog:allow-save` and `fs:allow-write-file`; there is
no blanket filesystem scope. The dialog grants access to the selected file.
PNG, ZIP, project JSON and template JSON all use the same awaited save adapter.
The desktop CSP permits local `data:`/`blob:` fetches used to assemble ZIPs.

Measured on Linux x64 with the committed config: a 3.7 MB stripped binary in a
1.8 MB `.deb`.

**Capacitor for Android.** Same reasoning: one WebView-hosted activity around
the existing bundle.

## What is committed, and what is generated

Committed (small, hand-written):

```text
src-tauri/
├── Cargo.toml                   # deps + size-tuned release profile
├── build.rs
├── tauri.conf.json              # window, CSP, bundle targets
├── capabilities/default.json    # core + save dialog + selected-file writes
└── src/main.rs                  # window + dialog/filesystem plugins
capacitor.config.json            # appId, appName, webDir
resources/icon.png               # 1024×1024 icon source
resources/splash.png             # 2732×2732 splash source
scripts/shrink-android-release.mjs
```

Generated by a build and **git-ignored**:

- `src-tauri/icons/` — the whole platform icon set (`.ico`, `.icns`, every PNG
  size) derived from `resources/icon.png` by `tauri icon`.
- `src-tauri/target/`, `src-tauri/gen/`
- `android/` — the Gradle project, from `npx cap add android`.

Keeping `android/` out of the repo avoids roughly two thousand generated files
and stops a committed project drifting away from the pinned Capacitor version.

## Building locally

### Desktop

Prerequisites: a [Rust toolchain](https://rustup.rs), plus on Linux:

```bash
sudo apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev patchelf
```

Then:

```bash
npm run app:desktop       # icons + release build for the current OS
npm run app:desktop:dev   # hot-reloading dev window against the Vite server
```

Installers land in `src-tauri/target/release/bundle/`.

### Android

Prerequisites: JDK 21 and the Android SDK (`ANDROID_HOME` set).

```bash
npm ci
npm run build
npm install --no-save @capacitor/core@^7 @capacitor/cli@^7 @capacitor/android@^7
npx cap add android                            # first time only
node scripts/configure-android.mjs              # native save bridge and manifest
npx @capacitor/assets generate --android       # launcher icons + splash
npm run app:android                            # sync + open Android Studio
```

Or build straight from the CLI:

```bash
node scripts/shrink-android-release.mjs        # turn on R8
cd android && ./gradlew assembleDebug          # sideloadable, debug-signed
```

Capacitor is installed with `--no-save` on purpose: it is only needed for the
mobile build, so `npm ci` stays lean for web and CLI users.

## CI: `.github/workflows/apps.yml`

Runs on a `v*` tag, manual dispatch, and pull requests that touch the app
packaging. Three jobs:

- **desktop** — matrix over Linux (`deb`, `rpm`), Windows (`nsis`) and macOS
  (one universal `dmg` for Apple Silicon and Intel). AppImage is deliberately
  excluded: it bundles WebKitGTK and weighs ~90 MB against ~6 MB for the deb.
- **android** — generates the Gradle project, builds a release APK + AAB and a
  debug APK, and signs the release when keystore secrets are present.
- **release** — attaches every artifact to the GitHub release on a `v*` tag.

Each job prints `ls -lh` of its output so a size regression is visible in the
log rather than only in a download.

### Size measures

| Where | What |
|---|---|
| `Cargo.toml` `[profile.release]` | `opt-level = "s"`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true` — dropping any one of these costs roughly 15–30 % of the stripped binary |
| Scoped native saves | only the dialog and filesystem plugins; no broad disk or shell access |
| `shrink-android-release.mjs` | R8 code shrinking + resource shrinking, which Capacitor's template leaves off |
| Bundle targets | small OS-native installers only |

The Android job uploads **both** the shrunk release APK and an unshrunk debug
APK. R8 removes ~1.5 MB of unused Capacitor/AndroidX classes; the keep rules in
`shrink-android-release.mjs` cover what Android resolves reflectively (Capacitor
plugins, `@JavascriptInterface` methods), and the debug APK is the fallback if a
future Capacitor version needs more.

### Signing the Android release

Without secrets, the job still produces an unsigned release APK/AAB plus a
debug-signed APK that testers can sideload. To get a Play-ready signed APK, add
four repository secrets:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ANDROID_KEY_ALIAS` | key alias |
| `ANDROID_KEY_PASSWORD` | key password |

The signing step is skipped automatically when `ANDROID_KEYSTORE_BASE64` is
empty, so forks without secrets are unaffected.

## Notes and gotchas

- **App version** comes from the root `package.json`: `tauri.conf.json` sets
  `"version": "../package.json"`, so there is one number to bump.
- **The CSP in `tauri.conf.json`** must list any host the app talks to. It
  currently allows Google Fonts plus the three AI translation providers in
  `src/ai/providers.ts` (OpenAI, OpenRouter, Google AI). Adding a provider there
  means adding its host here too, or its requests fail only in the desktop
  build. `style-src` keeps `'unsafe-inline'` because the editor styles most
  nodes with React `style` attributes; this was verified by running the built
  Linux binary under Xvfb and confirming the UI paints.
- **`identifier`** is `com.pixeldeck.app` in both shells. Change it in
  `tauri.conf.json` and `capacitor.config.json` together if you fork and
  publish your own builds.
- **iOS** is not wired into CI (it needs a paid Apple account and a macOS
  runner), but `capacitor.config.json` already carries the iOS block, so
  `npx cap add ios` works locally.

## Native export and mobile behavior

Android's committed `native/android/PixelDeckFilePlugin.java` is copied into the
generated project by `scripts/configure-android.mjs`. It uses
`ACTION_CREATE_DOCUMENT`, so users choose a destination for PNG, ZIP or JSON.
No storage, media-library, camera or all-files runtime permission is requested.
The document provider grants access to the selected URI only. Cancellation
returns to the editor; write failures remain visible and do not report success.
Choose ZIP for a batch to use one picker and preserve format/locale folders.
The browser-only folder export option is disabled in native shells.

The Capacitor App plugin handles Android Back: it closes an open modal or
mobile panel before minimizing the editor. Edge-to-edge margins and CSS safe
areas keep controls clear of system bars. Below 1024px, layers and properties
open separately over the canvas, with touch controls, a compact slide strip,
and a collapsible slide-options menu. The canvas refits on viewport changes;
two-finger gestures pan and zoom. Desktop panels remain side by side.

Native release verification should include saving PNG/ZIP/JSON, picker cancel,
and an unwritable provider on a Windows and Android device. Automated adapter
tests cover exact binary writes, cancellation and permission failures.
